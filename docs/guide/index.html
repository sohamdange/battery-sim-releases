// Before you start

How the pieces fit together

A simulation combines a pack (built from one cell) with a simulation cycle (the load it sees, day by day). The load is built in three levels, so nothing is duplicated.

  1. STEPSSub-cycleCurrent, power or rest steps, e.g. 1 C charge for 30 min
  2. ONE DAYDrive cycleSub-cycles in order, up to 24 hours
  3. CALENDARSimulation cycleRules that assign drive cycles to days
  1. 01

    Add a cell

    In the app: Cell Library → Add a cell

    A cell holds its identity, dimensions and voltage limits. Fill in the name, nominal voltage and capacity first. Then add a configuration: the physics to run it with.

    • {% include icon.html name="check" px=18 %}Circuit model: download the RC template CSV, fill in your measured SOC, OCV, R0 and RC values for each temperature, and upload it. It is checked as it uploads.
    • {% include icon.html name="check" px=18 %}Electrochemical model (with the add-on): enter the cell’s electrochemical parameter block, and record where the values came from.

    Common mistake: RC data at only one temperature. The solver interpolates between temperatures, so a single point gives wrong results elsewhere. If that is all you have, set a generous temperature extrapolation tolerance.

    {% include shot.html id="cell-builder" %}
  2. 02

    Build a pack

    In the app: Pack Builder

    Choose the cell, then arrange cells in layers using a rectangular or diagonal layout. Pick how they are wired (column-parallel, row-parallel or custom groups) and set the series and parallel link resistances. The builder shows the resulting voltage, capacity and limits, with 2D and 3D previews.

    For a thermal study, check the cell-to-cell thermal connections and set cooling to the air or a coolant plate.

    Common mistake: mixing up column-parallel and row-parallel. The name says which direction is in parallel, not which is in series.

    {% include shot.html id="pack-builder" %}
  3. 03

    Create sub-cycles

    In the app: Drive Builder → Sub-cycle Builder

    A sub-cycle is a list of steps: charge, discharge or rest, in current or power, for a set time, or until a voltage or SOC condition is met. Build them in the table, or upload a recorded schedule from CSV or Excel.

    Common mistake: no rest between charge and discharge. Real cells need rest for their voltage to relax.

    {% include shot.html id="subcycle-builder" %}
  4. 04

    Assemble the schedule

    In the app: Drive Cycle Builder, then Simulation Cycle Builder

    Chain sub-cycles into a drive cycle: one day of use, up to 24 hours. Then create a simulation cycle and use its Calendar tab to assign drive cycles to days, for example weekdays commute, weekends highway, with a default rule for every other day.

    Common mistake: conditions on one rule combine with AND. Months = January and Days = Monday fires only on Mondays in January. The first matching rule wins, so order rules from most to least specific.

    {% include shot.html id="calendar" %}
  5. 05

    Configure and run

    In the app: Simulations

    Select the pack and the simulation cycle. Choose the model first, then the cell configuration, then set the starting SOC, cell temperature and ambient temperature. Optionally switch on the thermal model, give cells their own capacity and resistance spread, and choose what the run records.

    Runs show live progress. You can start several at once, and stop one at any point while keeping the results so far.

    Common mistake: a high starting SOC with a charge-heavy schedule. The run stops at the upper voltage cut-off soon after it starts.

    {% include shot.html id="simulation-setup" %}
  6. 06

    Read the results

    In the app: Simulations → open a run

    Start with end SOC and peak temperature, then explore the pack, cell, overlapping and spatial views. Electrochemical runs with ageing add an Ageing panel. Export the time series to CSV, or create a PDF report.

    {% include shot.html id="results" %}

// FAQ

Questions while getting started

Why is the Run button disabled?

It needs both a pack and a simulation cycle selected. If both are, check that the pack has a valid cell and that a model and cell configuration are chosen.

What format do RC parameters need?

Use the template from the Cell Builder rather than writing one from scratch. Columns are named by direction and temperature, such as CHARGE_T25_soc or DISCHARGE_T05_r0, and each temperature needs both a charge and a discharge block. SOC must rise from row to row. A table that stops short of 0 % or 100 % is extended in a straight line, shown dashed in the plots.

Does the app include standard drive cycles?

No. Build your own from steps, or import a recorded schedule from CSV or Excel as a sub-cycle.

Can a pack mix different cells?

A pack uses one cell type. To study cell-to-cell differences, give each cell its own capacity and resistance factors in the simulation setup: typed, imported from CSV, or drawn from a measured spread with a repeatable seed.

Which model should I start with?

The built-in equivalent-circuit model: it is the fastest and needs only RC tables. Move to SPM, SPMe or DFN when you need diffusion limits, electrolyte effects or ageing. See the engines.

Is every loss counted as heat?

Not yet. Pack link resistance, cell contact resistance on the electrochemical models, and SEI film resistance lower the voltage correctly but are left out of reported heat. Each affected run’s log carries a warning.

Can I run several simulations at once?

Yes. Each run is independent, though they share your computer’s resources, so several heavy runs will each be slower.
